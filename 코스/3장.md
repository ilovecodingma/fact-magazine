# 3장 — 운영 (하루 한 바퀴)
먼저 `과외.md` 를 읽고 그 방식(독자 묻기·한 걸음의 짜임·확인 물음·기록)으로 진행한다. 한 바퀴를 돈 뒤 독자가 「오늘 사람이 정해야 했던 것」을 말해 보게 한다(과외.md 5절).
목표: 수집 → 묶기 → 대조 → 화면 → 홍보 문구 → 카드 → 점검까지 한 바퀴를 예행으로 돌리고, 결과를 열어 본다. **올리기·메일 발송은 하지 않는다.**

진행:
1. `/사이클` (= `python run.py 사이클`, 보통 1분 안팎). 단계마다 끝나면 독자에게 **아래 형식으로** 말한다.
   | 단계 | 독자에게 말할 것 | 열어 볼 곳 |
   |---|---|---|
   | [1/4] 수집·묶기·대조·화면·호·쇼츠 | 수집 N건·피드 N곳, 묶음 N건, 대조 통과 N/N, 만든 쪽 N개, 호 PDF 유무, 쇼츠는 만들었는지 「건너뜀」인지(ffmpeg 가 없으면 건너뛰고 설치 안내가 나온다) | `docs/`, `data/topics.json`, `logs/daily.md` |
   | [2/4] promo | 알림 문구·블로그 글 몇 개를 만들었는지 | `promo_out/` |
   | [3/4] 카드 | 공유용 카드 몇 장(png·svg)을 만들었는지 | `cards/` |
   | [4/4] 점검 | 문제 몇 건, 어떤 종류인지(예: 설정과 다른 주소로 찍힌 docs 면 「먼저 다시 찍기」) | 출력 마지막 줄 |
   0건이거나 건너뛴 단계는 숨기지 말고 이유와 함께 그대로 말한다. **뉴스 기능이 꺼진 사이트**(도구함·가게·모임 등)에서는 수집·묶기·대조와 promo·카드가 건너뛰어진다 — 출력에 「이 사이트는 뉴스 기능이 꺼져 있어 이 단계는 건너뜁니다」가 나오며, 독자에게도 그대로 말하고 사이트 화면과 점검만 한다.
2. 끝에 나오는 **「올릴 묶음」** 목록(promo_out/·cards/·shorts/·넘김/ 개수)을 독자에게 보여 주고 「여기서 사람이 올립니다」라고 안내한다. 올리지 않는다.
3. `python serve.py --open` 으로 방금 만든 사이트를 열어 보인다(내 PC 안에서만 열림). 화면이 없는 환경이면 창은 안 뜨므로 출력의 `http://127.0.0.1:포트/` 주소만 알려 준다(`--no-demo` 를 주면 조립 예시 안내도 빠진다).
4. 역할 나누기: `/역할 개발|콘텐츠|홍보` (`세팅.md`). 자동으로 돌리기(daily.yml)는 설명만 하고 켜지 않는다.
5. 마무리: 확인 물음 세 개, 「3장 끝」 기록.
