# 역할 세션 세팅 — 총괄이 개발·콘텐츠·홍보 세션을 두는 법

일을 나누면 한 세션이 한 가지에 집중하고, 서로 **파일로 넘기고 기록으로 남기는** 방식이 됩니다.

## 역할 네 개
| 역할 | 하는 일 | 읽을 것 |
|---|---|---|
| **총괄** | 시작·점검·조립 결정, 사람에게 묻는 자리 모으기, 나머지 세션에 일 나눠 주기 | `시작.md`, `CLAUDE.md` |
| **개발** | 저장소·빌드·키트·배포·점검(`doctor.py`·`audit.py`) | `역할/개발.md` |
| **콘텐츠** | 주제 고르기, 확인 노트·글·소설·만화 쓰기(공식 자료 대조), 제목·문구 | `역할/콘텐츠.md` |
| **홍보** | 블로그·영상·인스타용 글·카드·쇼츠 올릴 준비(올리기는 사람 승인), 운영 점검 | `역할/홍보.md` |

## 창(세션)을 더 열어 역할을 주는 법
1. 총괄 창은 지금 쓰는 창입니다. Claude Code 를 **같은 저장소 폴더에서 한 번 더 켭니다**(터미널·창을 하나 더).
2. 새 창에서 `/rename 개발`(또는 콘텐츠·홍보)로 이름을 붙입니다. 이름이 세션끼리 부르는 주소입니다.
3. **진행 방식은 모두 같게**: 시작할 때 `CLAUDE.md` 를 읽고, 끝나면 `기록/역할이름.md` 에 단계마다 적고(`기록/양식.md`), 넘길 것은 `넘김/` 폴더에 파일로 두고 받는 세션에 **한 줄**로 알립니다. 직접 확인한 것과 보고만 받은 것을 나눠 적습니다.
4. 첫 입력 한 줄(각 창에 한 번만):
   - 개발: `이 폴더는 에이전트 하네스 저장소야. 너는 「개발」 역할이야. CLAUDE.md 와 역할/개발.md 를 읽고, 넘김/ 과 기록/ 규칙대로 일해. 저장소 파일은 너만 고치고, 로그인·공개는 나에게 물어.`
   - 콘텐츠: `… 너는 「콘텐츠」 역할이야. 역할/콘텐츠.md 를 읽고, 공식 자료로 확인한 것만 노트·글로 써서 넘김/notes/ 와 넘김/posts/ 에 둬. 저장소 파일은 직접 고치지 마.`
   - 홍보: `… 너는 「홍보」 역할이야. 역할/홍보.md 를 읽고, promo.py·card.py 결과로 올릴 준비만 해. 올리기는 내 승인 뒤에만.`
5. 총괄은 각 창에 일을 나눠 주고(「넘김/ 에 notes 2건 두면 알려 줘」), 결과를 모아 사람에게 보여 줍니다.

## 넘김·기록 폴더
- `넘김/` : 세션끼리 주고받는 파일(예: `topics.json`, `고른주제.md`, `notes/*.json`, `shorts/`). 받는 세션이 읽고 한 줄로 답합니다.
- `기록/` : 단계마다 한 칸(받은 지시 / 한 일 / 결과(직접 확인·보고만 받음 구분) / 막힌 곳·고친 것 / 사람이 정해야 하는 것 / 주고받은 메시지).
- 저장소 파일(코드·`docs/`)은 **개발만** 고칩니다. 다른 세션이 고쳐야 하면 개발에 한 줄로 요청합니다.

## 세션 하나로만 할 때
창을 여럿 열지 않고 총괄 하나가 **작은 에이전트(서브에이전트)를 불러** 역할을 나눠 맡길 수 있습니다.
- 총괄이 Agent 도구로 「콘텐츠 역할로 확인 노트 2건 써 줘」 같은 일을 한 번에 하나씩 맡기고, 결과 파일을 `넘김/` 에서 받습니다.
- 서브에이전트에게는 **필요한 파일 경로와 규칙(공식 자료로 확인한 것만, 올리지 않기)** 을 적어 주고, 돌아온 결과는 총괄이 직접 확인한 뒤 사람에게 전합니다.
- 한꺼번에 많이 부르지 않습니다(비용·혼선). 처음에는 한 역할씩.

## 운영 한 바퀴(예)
개발: 수집·묶기 → `넘김/topics.json` → 콘텐츠: 주제 고르기·노트 쓰기 → 개발: 대조·빌드·호·쇼츠·promo·카드·올리기·주소 점검·상태 → 홍보: 올릴 준비 → 사람: 승인. 각 단계의 시각과 한 줄 메시지를 `기록/` 에 남깁니다.
